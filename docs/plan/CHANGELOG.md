# 得物采集项目文档更新记录

本文件用于记录 [得物库存货号价格与销量采集项目总规划](./2026-08-09-dewu-collection-master-plan.md) 的每次规则和执行口径更新。文档更新应先修改总规划，再在这里新增一条记录；不要覆盖历史记录。

`docs/plan` 目录只保留本总规划和本更新记录，不保存阶段性计划副本或讨论中间稿。

## 2026-08-09

### 增加初学者 Codex 协作进度系统

- 新增 `docs/development-progress/`，通过 `CURRENT_STEP.md`、人工进度板、窗口/角色规则、标准 17 步模块循环、各 Wave 清单、回滚手册和可复制提示词指导用户逐步完成完整软件开发。
- 当前第一步固定为 `G00.1`：新建长期 Coordinator，只读审计本地 Git 与远程 GitHub 状态；不直接启动 MOD-00 Developer。
- 默认启用 `LEARNING_MODE`，同时最多一个生产 Developer；W1 按 Environment、Jobs、Evidence、Export 串行体验，用户明确切换后才可并行。
- 固化 Coordinator 长期复用、每模块新建 Developer、每次验证新建 QA、每次审查新建 Reviewer 的窗口生命周期。
- 将修改、stage、commit、push、draft PR、ready、merge、清理 worktree、系统安装、设备修改和进度前进拆为独立授权。
- 根 `AGENTS.md` 增加 Beginner Learning-Mode Progress Gate，要求 Agent 只执行 `CURRENT_STEP` 的一个原子步骤并强制停止，未经用户批准不得自动前进。

### 影响范围

- 后续 Agent 不得一次完成整个模块或 Wave，即使技术上具备执行能力。
- GitHub 继续作为代码与依赖状态事实来源；进度目录记录用户的学习和操作位置，两者冲突时必须暂停并由 Coordinator 解释。
- 本次创建进度文档，不代表治理基线已经 commit/push，也不代表 Issue #1 的开发已经开始。

## 2026-08-09

### 增加根级 AGENTS.md 与安全化开发原则

- 新增仓库根目录 `AGENTS.md`，使 Codex 在每个开发、QA、审查和集成任务开始时自动获得项目目标、模块所有权、Wave 依赖门和 GitHub 工作流。
- 将“一任务一角色”固化为常驻约束：模块开发、独立 QA、只读审查和集成分别由不同 task/chat 承担；作者自测不能替代独立 QA，也不能自行审查或合并。
- 纳入最简单可用实现、最小端到端切片、关注点分离、成熟依赖优先、先审计现有依赖、长期架构决策和参考已验证模式等八项原则。
- 对“不保留向后兼容”增加数据安全边界：第一版未发布内部代码可以直接移除旧实现，但真实库存、证据、断点、账号和设备数据不得删除；持久数据或已发布契约变更必须备份、演练、验证并可逆回滚。
- 增加项目专属 `Code Review Rules`，阻止逐货号 UI 生产采集、客户端自行销量排序、Schema 静默 fallback、秘密泄漏、跨模块越权、非原子断点和超出 6 列的导出。

### 影响范围

- 后续新建 Codex task 将从根目录自动读取这些开发约束；模块级例外只能收紧规则，不能放宽安全、角色分离和发布门禁。
- 本次只增加治理文档，不代表任何模块代码、环境安装、Live Frida 测试或 GitHub PR 已完成。

- 将远程仓库固定为 `Wmx-5Percent/dewu-price-check`，GitHub Issues、Pull Requests 和 Actions 分别作为进度/依赖、代码合并和质量门禁的唯一事实来源。
- 拆分 `MOD-00` 至 `MOD-08` 九个单一职责模块，明确每个模块的允许修改范围、直接依赖和完成定义。
- 建立 `W0` 至 `W6` 开发波次；关键路径为 `MOD-00 → MOD-01 → MOD-02 → MOD-03 → MOD-07 → MOD-08`，Jobs、Evidence 和 Export 在 `W1` 并行。
- 固化“一名开发 agent 只负责一个模块”的规则；每个模块必须使用独立 Codex task/chat、worktree、分支、Issue 和 draft PR，禁止单一聊天窗口或单一 agent 承担整个应用的 0–1 开发。
- 增加集成 agent、QA agent 和总协调 agent 的禁止越界规则；跨模块修改必须先走公共契约变更。
- 确认 Node.js 22.x、`frida@17.16.4`、`exceljs@4.4.0`、`ajv@8.17.1`、Java 17、Android API 35 Google APIs arm64 和 Frida Server 17.16.4 依赖基线。
- 增加 GitHub Issue/分支/PR 命名、依赖表达、状态评论、合并顺序、CI 检查、Dependabot 和 Wave 监控协议。
- 明确目标 GitHub 仓库为公开仓库，真实库存、APK、会话秘密、原始响应、设备标识和未脱敏日志不得提交。
- 本地仓库已连接远程 `origin`；GitHub 已建立四组治理标签、9 个模块父 Issue（#1–#9）和 W6 全量运行 Issue #10。初始只有 #1 为 `ready`，其他 Issue 均按依赖标记为 `blocked`。

### 影响范围

- 后续开发只能按模块 Issue 和 Wave 依赖门启动，不允许用一个 agent 或一个聊天窗口连续实现全部模块。
- 主分支禁止直接开发；任何模块代码都必须通过独立 PR、CI 和非作者审查。
- Live AVD/Frida 测试只能在受控 self-hosted runner 手动执行，GitHub-hosted runner 只运行无秘密的离线测试。

## 2026-08-09

### 将正式采集路线升级为 Frida 响应级采集器

- 变更文件：`docs/plan/2026-08-09-dewu-collection-master-plan.md`
- 将正式批量流程从逐货号 UI 点击、UI XML 和尺码滚动改为：Frida Agent 在得物进程内复用 App 登录态、设备参数、请求签名和网络客户端，直接获取搜索、商品详情及尺码报价响应。
- 固化“请求明确使用销量降序参数并选择服务端第一条”的规则；禁止获取默认结果后在采集器内部自行按销量排序。
- 明确 UI 只用于首次登录、协议发现、同刻准确性对照和人工复核，不再作为生产批量热路径。
- 增加按得物版本管理的 `ProtocolProfile`、Frida RPC、脱敏响应证据、Schema 版本守卫和会话秘密不落盘规则。
- 第一版产品形态确定为“跨电脑 Node.js CLI + 独立受控 Root Android Emulator + Frida Server”；保留现有未 Root AVD，不对其执行 Magisk Root。
- 固定首个 Profile 为得物 `5.95.1 (versionCode 1101)`，首个 Frida 客户端/Server 版本为 `17.16.4`，两端版本必须一致。
- 并发策略确定为自适应 `1 → 2 → 4`；遇到 429、登录失效、风险响应、Frida 断连、Profile 不兼容或 Schema 漂移时降速或全局暂停。
- 保持交付 Excel 的 6 列契约不变；商品 ID、variant/sku ID、搜索排名、Profile 版本、采集时间和响应证据只保存于内部 JSON。
- 增加协议 fixture、跨类别同刻 UI 对照、经批准测试集性能、断点、阻塞和第二台干净电脑可移植验收。

### 数据与证据澄清

- 真实库存与派生样本均为本地运行数据，不提交、不在公开文档中记录文件名、范围或业务数量；后续运行始终动态建立基线。
- 经批准验证输入不包含得物价格、销量或原始响应，不能作为采集准确性金标。

### 影响范围

- 原有 ADB/UI 脚本降级为协议发现与人工对照工具；现有逐货号 UI 结果不自动视为响应级采集器验收通过。
- 后续实现顺序改为 Root AVD/Frida 环境、协议发现、进程内 RPC、批量编排、可移植验收和全量运行。
- Android 伴生 APK、普通非 Root 真机、公开应用商店分发和完全独立 API 客户端移出第一版。

## 2026-08-09

### 补充可移植 Android App/脚本产品化开发计划

- 在总规划第 9 节增加桌面控制器/Android 脚本和 Android 原生 App 两种部署形态，明确先做跨设备桌面控制器，再评估原生 `AccessibilityService` 版本。
- 增加设备适配层、得物 UI Profile、响应驱动状态机、证据保存、断点恢复和 6 列结果导出的分层方案。
- 明确支持 USB ADB、无线 ADB 和 Android Simulator；设备必须通过 serial/udid 选择，禁止绑定当前电脑、模拟器名称、固定分辨率或固定坐标。
- 将“真实点击得物搜索结果页的‘销量’控件，等待排序刷新后点击第一条”固化为强制动作；仅在程序内部读取销量后排序不再视为通过。
- 将页面等待改为基于 UI 节点、文本、结果变化和列表刷新状态的响应驱动，取消固定 10 秒任务间隔和等待商品视频播放的做法。
- 增加无障碍服务权限、应用商店披露、风控/验证码不绕过、跨设备测试矩阵和产品化验收标准。

### 变更原因

本轮在 Android Simulator 上人工观察到默认搜索排序并非销量排序，必须真实点击“销量”后再选择第一条；同时固定等待和设备坐标会限制脚本迁移到其他电脑、真机和模拟器，因此先将可移植实现方案写入总规划，作为后续开发和验收依据。

### 影响范围

- 规划文件：`docs/plan/2026-08-09-dewu-collection-master-plan.md`
- 后续实现：设备适配层、得物 UI 选择器/状态机、跨设备测试和 Android App 原型。
- 既有测试样本采集结果不因本条规划记录自动视为完成；必须按新的“销量真实点击”规则重新采集并验收。

## 2026-08-09

### 建立项目级总规划

- 将原 `2026-08-09-dewu-pilot-20-collection-rules-v2.md` 提升并更名为 `2026-08-09-dewu-collection-master-plan.md`。
- 明确该文件是项目当前唯一的执行总规划，20 个货号只是分批执行策略，不再作为计划名称或项目范围。
- 固化已确认的操作顺序：进入得物“购物/购买”页面，在该页面搜索货号，按销量降序，直接点击第一条，进入商品页后点击“立即购买”，采集页面显示的全部尺码、对应卖价和商品级总销量。
- 明确不做页面货号二次确认，不假设尺码码制，不做库存尺码与得物尺码映射。
- 固化交付 Excel 的 6 列：货号、得物商品名、得物显示尺码、得物卖价（元）、总销量、异常或人工复核说明。
- 固化批次边界、全局阻塞即停止、内部调试字段与交付 Excel 分离等执行要求。
- 保留旧计划路径作为兼容入口，但不再把它作为规则正文或项目计划名称。
- 澄清 Excel 的“总销量”列可以保存页面销量原文，但不再额外建立“销量原文”列，也不输出销量下限、销量近似或销量来源。

### 变更原因

根据本轮人工检查和对齐结果，旧计划中的页面货号二次核验、库存尺码映射和销量下限导出会导致采集路径不一致或污染交付表，因此统一移出当前阶段。

## 2026-08-09

### 转为输入文件无关的自动化总规划

- 删除总规划中绑定当前库存文件的链接、库存行数、货号数量和类别数量。
- 将数据范围改为由每次运行传入的库存文件动态读取、去重和建立基线。
- 将批次大小、输入文件、筛选类别、重试和断点恢复定义为运行参数，不再把某一批次或某个文件当作项目基线。
- 补充全自动化执行器需要具备的输入检查、任务生成、逐货号采集、状态落盘、阻塞暂停和断点续跑步骤。
- 删除 `docs/plan` 下的历史计划、阶段性 Pilot 入口和旧全量计划，只保留 master plan 与 CHANGELOG。
- 明确讨论中间稿不做长期保存；每次讨论只将最终确认结果更新到 master plan，并在 CHANGELOG 留下记录。

### 变更原因

未来库存文件的行数、货号数量和类别分布可能变化，但得物采集任务不变。总规划必须描述稳定的任务逻辑和自动化契约，不能把某一次运行的数据快照当作长期基线。
